**推荐方案**
采用 `frontend/` 独立 Vite SPA，生产构建后由 Spring Boot 同源托管在 `/app` 下。原因是后端已有 `GET /{shortUri}` 短链跳转入口，如果前端使用 `/login`、`/dashboard` 这类根路径，会和短码路由冲突：[LinkController.java](/Users/haosiyuan/Documents/Study/agent-study/shortlink/src/main/java/dev/haotangyuan/shortlink/controller/core/LinkController.java:34)。`/app/**` 前缀可以保留短链根路径，同时支持 SPA 刷新。

备选：
| 方案 | 说明 | 取舍 |
|---|---|---|
| A. `/app` 同源托管 | `frontend/` 源码，Vite build 产物进入 Spring static，新增 `/app/**` fallback | 推荐；无 CORS，最贴合纯后台项目 |
| B. 前后端分离部署 | Vercel/Nginx 独立前端，`VITE_API_BASE_URL` 指向后端 | 需要后端 CORS，部署链路多 |
| C. HashRouter 根路径 | `/#/login`、`/#/dashboard`，几乎不改后端 | URL 不够干净，不利于后续扩展 |

**技术选型**
用 `React + TypeScript + Tailwind CSS + Vite`，补充依赖建议：

| 图表 | `recharts` |
| 图标 | `lucide-react` |
| UI | shadcn 风格本地组件，Tailwind token 化，不引入重型组件库 |

**接口对齐**
统一响应是 `{ code, message, data, requestId }`；`code === "0"` 才算成功。

| 模块 | 接口 |
|---|---|
| 用户 | `GET /api/short-link/admin/v1/user/{username}`、`GET /actual/user/{username}`、`GET /user/exists?username=`、`POST /user`、`PUT /user`、`POST /user/login`、`POST /user/check-login`、`DELETE /user/logout` |
| 分组 | `POST /group`、`GET /group`、`PUT /group`、`DELETE /group?gid=`、`POST /group/sort` |
| 链接 | `POST /create`、`POST /create/batch`、`POST /update`、`GET /page?gid=&current=&size=&orderTag=` |
| 回收站 | `POST /recycle-bin/save`、`GET /recycle-bin/page?gidList=&current=&size=`、`POST /restore`、`POST /remove` |
| 统计 | `GET /stats`、`GET /stats/group`、`GET /stats/access-record`、`GET /stats/access-record/group` |
| Token | `POST /token`、`GET /token`、`DELETE /token/{id}`、`PATCH /token/{id}/status?enable=` |
| URL 标题 | `GET /title?url=` |
| Core API | `/api/short-link/v1/*` 与链接、回收站、统计、标题基本同构，供 API Token 调用；后台 UI 默认用 admin 接口 |
| 跳转 | `GET /{shortUri}`，前端不拦截，短链用户直接访问 |
