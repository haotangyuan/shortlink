# 技术亮点

## 1. 短码生成：号段 + 仿射置换

短码生成采用号段模式 + 仿射变换 + Base62 编码，兼顾性能和不可预测性。

**号段模式**：通过 Redis `INCRBY` 一次获取 10000 个序号，减少网络往返。号段剩余 20% 时触发异步预取，避免耗尽时阻塞。

**仿射置换**：`y = (a * i + b) mod 62^6`，将连续序号打散为不可预测的短码。参数 `a`、`b` 在启动时随机生成并持久化到 Redis，保证重启后一致性。

**Base62 编码**：使用 `[0-9a-zA-Z]` 共 62 个字符，6 位短码可表示约 568 亿种组合。

```
Redis INCRBY → 批量取号段 → 本地号段池 → 取序号 i → 仿射变换 → Base62 → 6位短码
```

## 2. 多级缓存：降低尾延迟

跳转请求对延迟极其敏感，采用四级缓存策略：

| 层级 | 组件 | 作用 | TTL |
|------|------|------|-----|
| L1 | Caffeine | 热点本地缓存，避免网络开销 | 10min |
| L2 | Redis | 分布式缓存，多实例共享 | 跟随有效期 |
| L3 | Bloom Filter | 快速否定不存在的短码 | 持久化 |
| L4 | 空值缓存 | 防止穿透，缓存不存在的 key | 30min |

**本地互斥锁**：缓存未命中时使用 `Caffeine + ReentrantLock` 做本地锁，避免分布式锁的尾延迟放大问题。双重检查确保并发安全。

## 3. 异步统计：解耦跳转与持久化

跳转时立即返回 302，统计通过 Redis Stream 异步处理：

1. **生产**：跳转时 `XADD` 写入统计消息，不阻塞跳转
2. **消费**：Consumer Group 消费，支持多实例水平扩展
3. **幂等**：messageId 唯一索引 + Redis 标记双重保障
4. **恢复**：定时任务扫描 Pending 消息，自动重试超时未 ACK 的消息
5. **UV/UIP**：HyperLogLog + Lua 脚本原子计算增量
6. **多维统计**：地区、操作系统、浏览器、设备、网络、访问日志

## 4. 分库分表：水平扩展

ShardingSphere 按 `gid` 哈希分 16 张表，避免单表数据量过大：

```
t_link_0, t_link_1, ... t_link_15       ← 短链接表
t_group_0, t_group_1, ... t_group_15    ← 分组表
t_goto_0, t_goto_1, ... t_goto_15      ← 跳转统计表
```

分片键：`gid`（链接表）、`username`（分组表）、`full_short_url`（跳转表）。

## 5. 限流与流控

**API 限流**：Guava RateLimiter 对创建、跳转、统计等接口分别限流。

**用户级流控**：Redis Lua 滑动窗口脚本，按用户维度限制请求频率，防止恶意调用。

**流控过滤器**：`FlowLimitFilter` 在过滤器层统一处理，业务代码无感知。

## 6. 安全与认证

- **Admin 接口**：Session Token 认证，登录后返回 Token
- **Core 接口**：API Token 认证，后台管理页面创建
- **敏感数据加密**：AES 加密存储用户手机号、邮箱
- **用户流控风控**：按用户维度限制请求频率

## 7. MCP 集成

标准 Model Context Protocol (MCP) 服务端，SSE 端点 `/api/mcp`，暴露 `createShortLink` 工具供 AI Agent 调用。

## 8. Lua 脚本原子操作

Redis Lua 脚本保证原子性，用于：
- HyperLogLog 增量计算（UV/UIP）
- 滑动窗口限流
- 统计数据批量更新

脚本位于 `src/main/resources/lua/`。

## 11. AI 运营助手：ReAct Agent + SSE 流式交互

基于 AgentScope Java 2.0 构建 ReAct Agent，为短链接运营提供智能数据分析能力。

**ReAct 推理链**：Agent 采用 Reasoning → Acting → Observation 循环，根据用户意图自主选择 6 个分析工具（分组列表、分组统计、链接对比、单链详情、异常检测、健康检查），最多迭代 10 轮完成复杂分析。

**SSE 流式架构**：后端通过 `SseEmitter` 实时推送 `text`（文字增量）、`tool_call`（工具调用）、`session_id`（会话标识）、`done`（完成信号）四种事件类型，前端手动解析 SSE 协议实现流式渲染。

**多轮对话上下文**：会话和消息持久化到 MySQL（`t_ai_session` + `t_ai_message`），每次对话加载最近 20 条历史消息构建上下文，Agent 可理解追问和上下文引用。

**异步线程上下文传递**：Agent 响应式流在独立线程执行，通过局部变量捕获 `UserContext.getUsername()` 解决 TransmittableThreadLocal 跨线程丢失问题。
