# 仓库治理与限流精简

## 背景

项目文档此前分散在两个目录，且保留了已不再使用的 OpenSpec 规格。README 缺少可直接复用且与实现一致的简历描述；RateLimitFilter 对四个创建接口包含重复的限流分支。

## 方案

- 将项目文档统一迁移至 notebook/，并将项目分析文档一并迁入；docs/ 只保留 superpowers/ 产物。
- 删除根目录空 lib/ 和完整历史规格目录，保留前端运行依赖 frontend/src/lib/。
- 在 README 增加五点简历描述与维护规则，并同步更新所有迁移后的 Markdown 链接和开发准则。
- 为 RateLimitFilter 增加特征测试，锁定创建、跳转、统计与拒绝请求的限流行为；使用路径到令牌数的私有映射合并四个创建接口分支。

## 影响范围

- 文档目录已统一迁移至 notebook/，README、CLAUDE 和项目分析文档中的路径已同步更新。
- 删除 OpenSpec 配置和历史变更记录，不涉及业务代码、数据库、缓存键或接口协议。
- 限流重构保持前台/后台单条创建消耗 1 个令牌、批量创建消耗 5 个令牌，跳转与统计限流逻辑不变。

## 测试

- mvn test：8 项测试通过。
- npm test：2 个测试文件、3 项测试通过。
- npm run build：TypeScript 编译与 Vite 生产构建通过；构建保留现有的单个产物超过 500 kB 提示。
- 目录、旧路径引用和 git diff --check 静态检查通过。
